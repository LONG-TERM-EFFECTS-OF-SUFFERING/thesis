\chapter{Reference framework}

\section{Glossary}

\begin{itemize}
    \item \textbf{Methodological transparency}: a practice in research where the methods, procedures and analysis techniques are documented and shared in sufficient detail to allow other researchers to understand exactly how the study was conducted.

    \item \textbf{API (Application Programming Interface)}: \enquote{a set of functions and procedures that allow the creation of applications which access the features or data of an operating system, application, or other service, enabling third parties to use the functionality of that software application}. \autocite{sciencedirect_api}

    \item \textbf{LLM (Large Language Model)}: \enquote{a narrow artificial intelligence (AI) system that has been trained on a massive amount of text data to interpret natural language and generate human-like responses to text-based prompts or questions}. \autocite{almarie2023llm}

    \item \textbf{Computational reproducibility}: \enquote{obtaining consistent results using the same input data, computational methods and conditions of analysis}. \autocite{nasem2019reproducibility} In the context of API-driven platforms, computational reproducibility applies to the data processing and analysis stages while the stored raw payloads exist; in OpenTube, platform terms limit that period to 30 days after collection (Subsection~\ref{subsec:ethics_privacy_and_terms_compliance}).

    \item \textbf{Data provenance (or documented provenance)}: the documented origin, chain of custody, execution context and transformation history of a dataset. In API data collection, provenance requires recording full request metadata—including query parameters, pagination tokens, execution timestamps and, for as long as platform terms permit, raw JSON responses—so that the way data were retrieved can be traced.

    \item \textbf{Methodological auditability}: the characteristic of a system or study that enables external reviewers to inspect, verify and trace every stage of data collection and processing through accessible logs, raw payloads retained for as long as platform terms permit and documented parameter configurations, even when underlying third-party endpoints exhibit temporal result decay.

    \item \textbf{Replicability}: \enquote{an attempt by a second researcher to replicate a previous study is an effort to determine whether applying the same methods to the same scientific question produces similar results}. \autocite{nasem2019reproducibility}

    \item \textbf{Social network site}: \enquote{a networked communication platform in which participants (a) have uniquely identifiable profiles that consist of user-supplied content, content provided by other users and/or system-level data; (b) can publicly articulate connections that can be viewed and traversed by others; and (c) can consume, produce and/or interact with streams of user-generated content provided by their connections on the site}. \autocite{aichner2021socialmedia}

    \item \textbf{Social listening}: \enquote{monitoring and analyzing conversations that take place on social and digital channels to gain insights into customer opinions, preferences and trends. It involves tracking mentions of a brand, product, or relevant keywords and analyzing the sentiment and context of these conversations}. \autocite{emplifi_sociallistening}

    \item \textbf{Sentiment analysis}: \enquote{can be stated as the procedure to identify, recognize and/or categorize the users' emotions or opinions for any service like movies, product issues, events, or any attribute as positive, negative, or neutral}. \autocite{bordoloi2023sentiment}

\end{itemize}

\section{State of art}

\subsection{LLM-based query generation}

Recent advancements in natural language processing have demonstrated the efficacy of Large Language Models (LLMs) in translating informal user intent into structured technical commands. A prominent application of this capability is Text-to-SQL generation, which lowers the barrier to entry for interacting with complex database systems by allowing users to query data using natural language. The reliability of this translation process has improved significantly with modern models; as noted by \textcite{zhu2024largelanguagemodelenhanced}, the enhanced inference and generalization capabilities of current LLMs allow them to generate correct SQL queries with a high degree of accuracy. For instance, models such as GPT-4 have achieved state-of-the-art performance on benchmarks like Spider, outperforming previous rule-based approaches in natural language understanding.

Beyond database querying, this capability extends to API integration, which can be achieved effectively when clear documentation is available. Recent work demonstrates that LLMs can generate accurate API calls directly from natural language instructions \autocite{tesfagiorgis2023large}. This application validates the proposed strategy of using pre-trained LLMs as semantic translation layers between user intent and technical system interfaces, proving that effective integration is achievable without the need for resource-intensive model training or domain-specific fine-tuning.

This established precedent supports the proposed architecture of using a pre-trained LLM as a natural language interface for the YouTube Data API, where user queries are translated into valid API parameters through semantic understanding of intent and systematic mapping to API specifications.

While the \texttt{search.list} endpoint relies on a bounded set of roughly ten query parameters, traditional form-based interfaces force researchers to manually translate high-level research questions into platform-specific parameter logic (e.g., mapping conceptual timeframes into ISO-8601 strings or structuring keyword filters for API syntax). The rationale for integrating an LLM natural language interface is semantic mapping rather than syntactic simplification. The LLM parses informal, domain-specific research intents (e.g., \enquote{Find news videos about climate policy in Colombia published during late 2024 order by view count}) and automatically infers the optimal combination of \texttt{q}, \texttt{publishedAfter}, \texttt{publishedBefore}, \texttt{regionCode} and \texttt{order} parameters. By pairing this automated semantic translation with a human-in-the-loop verification step where researchers inspect and edit the generated parameter schema prior to execution, OpenTube lowers technical entry barriers without sacrificing parameter accuracy or system transparency.

Furthermore, although LLMs are inherently stochastic, this non-determinism does not compromise the application's scientific rigor. The LLM acts solely as an interactive translation assistant that proposes candidate API parameters from natural language prompts. The canonical, reproducible artifact of a collection session is not the LLM's raw output stream, but the \textbf{human-validated structured parameter object} (\texttt{structured\_query\_params}) stored in the database alongside the corresponding \texttt{llm\_prompt\_version}. Once reviewed and confirmed by the researcher, these structured parameters serve as the deterministic input to the collection engine and are permanently logged in \texttt{api\_request\_logs} to ensure complete traceability.

\subsection{Commercial social listening tools}

Commercial social listening tools represent the closest commercial solutions to the proposed system in terms of core functionality, offering capabilities such as multi-platform monitoring, sentiment analysis and trend detection. Prominent platforms like Hootsuite (with Talkwalker) and Meltwater are optimized for business intelligence, brand monitoring, marketing analytics and customer experience management across multiple social media platforms simultaneously, including Facebook, X (formerly Twitter), Instagram, TikTok, LinkedIn, YouTube and Reddit, processing millions to hundreds of millions of data sources daily \autocite{talkwalker, meltwater}.

However, despite functional similarities, these commercial solutions operate under a fundamentally different scope and design philosophy. These tools prioritize real-time monitoring, competitive intelligence and actionable business insights over methodological transparency and scientific reproducibility. Their proprietary algorithms, closed-source architectures and lack of access to raw data or processing methods make it impossible for researchers to verify results, replicate analyses, or understand the underlying computational processes, requirements that are essential for rigorous academic research.

Furthermore, enterprise pricing models (often ranging from thousands to tens of thousands of dollars annually) create significant accessibility barriers for individual researchers, small research teams and academic institutions with limited budgets. While these platforms offer sophisticated AI-powered analytics and visualization capabilities suitable for corporate decision-making, they are inherently unsuitable for transparent, reproducible scientific research where methodological clarity, open access to data processing methods and cost-effective accessibility are fundamental requirements. This gap between commercial enterprise tools and academic research needs establishes the motivation for developing a research-focused social listening platform that maintains methodological transparency while providing the analytical capabilities required for scientific study.

\subsection{Existing open-source and academic tools}

The ecosystem of open-source and academic social media analysis tools includes both component-level software libraries and specialized research platforms. At the component level, standalone Python wrappers (e.g., \texttt{youtube-search-python} \autocite{youtube_search_python}), natural language processing libraries (e.g., VADER, TextBlob, spaCy), and visualization packages (e.g., Matplotlib, Plotly) provide programmatic building blocks. However, relying solely on component libraries requires researchers to write custom scripts, manage API authentication manually, and construct ad-hoc data pipelines, introducing potential points of failure in methodological documentation and reproducibility.

At the platform level, academic projects such as YouTube Data Tools (YTDT) by \textcite{youtube_data_tools} and the 4CAT Capture and Analysis Toolkit by \textcite{peeters20224cat} have made substantial contributions to reproducible social media research. YTDT provides web-based modules for extracting network structures, video metadata, and comment threads from YouTube. 4CAT offers a robust, multi-platform analysis environment designed for digital humanities and social science researchers, supporting modular data collection, analytical transformations, and visual outputs.

Rather than claiming to be the sole platform capable of social media collection and analysis, OpenTube establishes its scientific value through a distinct combination of architectural differentiators tailored specifically for API-driven research workflows:

\begin{enumerate}
    \item \textbf{Natural Language Interface (NLI) for semantic query translation}: unlike existing platforms that require researchers to manually construct API search syntax and format parameter bounds (e.g., ISO-8601 timestamps), OpenTube integrates an LLM translation layer. This interface maps informal research questions directly into valid API query parameter objects (\texttt{structured\_query\_params}) with human-in-the-loop review, lowering technical barriers while enforcing parameter validity.

    \item \textbf{Granular per-request provenance and quota logging}: while existing tools capture high-level dataset metadata, OpenTube records complete execution context down to individual HTTP requests in \texttt{api\_request\_logs} and \texttt{collection\_runs}. Each API call logs exact parameter bounds, \texttt{part} and \texttt{fields} restrictions, pagination tokens, HTTP status codes, quota costs, and raw JSON payloads (\texttt{raw\_payload}), establishing full auditability for third-party API data collection.

    \item \textbf{Localized, end-to-end workspace integration for social science research}: OpenTube delivers a unified, containerized pipeline (collection $\rightarrow$ processing $\rightarrow$ sentiment analysis $\rightarrow$ interactive visualization) specifically designed for project-level research workspaces. The platform is pre-configured and validated for Spanish-language discourse and regional computational social science projects, such as the PROMUEVA project at Universidad del Valle \autocite{promueva_project}.
\end{enumerate}

\subsection{Key academic studies}

The academic community has increasingly utilized YouTube as a significant data source for social science research. This research is diverse: some studies focus on video content (such as education, health information, or politics); others investigate the recommendation algorithm (examining its relation to news, misinformation, or radicalization); and a significant portion specifically analyzes user comments to understand topics like hate speech, political ideology, gender differences, or sentiment \autocite{deubel2024overview}.

\section{Theoretical framework}

\subsection{Interactions in the YouTube social network}

Understanding the structure of interactions within YouTube as a social network is fundamental to designing a social listening tool that captures meaningful data for research purposes.

\paragraph{Roles within the YouTube ecosystem}

\textcite{sui2022youtube} identify three primary roles that individuals occupy within the YouTube social network, each representing progressively higher levels of platform engagement.

\begin{itemize}
    \item \textbf{Viewer}: represents represents the most basic level of engagement, consisting of individuals who interact with YouTube solely through passive video consumption. This role requires no account and represents the broadest, least specific form of platform engagement.

    \item \textbf{User}: extends beyond passive viewing to include active engagement mechanisms available through a Google account, such as leaving likes or dislikes on videos, posting comments, replying to existing comments, liking or disliking comments and subscribing to channels.

    \item \textbf{Creator (or YouTuber)}: occupies the highest degree of platform engagement, actively producing content by posting videos, writing descriptions, curating channels and building subscriber communities that can elevate them to micro-celebrity status.
\end{itemize}

These roles are not mutually exclusive (creators are simultaneously users and viewers) but they represent distinct analytical categories for understanding platform interactions.

\paragraph{Interaction mechanisms}

Building upon the framework proposed by \textcite{giglietto2012open}, \textcite{sui2022youtube} categorize YouTube interactions into distinct types based on the nature of engagement.

\begin{itemize}
    \item \textbf{Audience interactions}: the views.

    \item \textbf{Social interactions}: the likes, dislikes and comments.

    \item \textbf{Platform interactions}: the metadata like title, date, ID, etc.
\end{itemize}

\paragraph{Extended data categories}

\begin{itemize}
    \item \textbf{Engagement metrics}: quantifiable representations of viewer and user interactions with creators and the platform, including views, likes/dislikes, comments, comment replies, comment likes/dislikes and subscriber counts. These metrics provide measurable indicators of content popularity, audience sentiment and community activity.

    \item \textbf{Video/channel characteristics}: structural data independent of user interactions, including total video uploads, video duration, channel start date, video posting frequency and upload schedules. These characteristics enable analysis of creator behavior patterns and content production strategies.

    \item \textbf{Textual data}: language and discourse elements available for qualitative and quantitative analysis, including video transcripts (extractable through YouTube's built-in transcript function), video titles, video descriptions, channel \enquote{About} pages, video tags, comments and comment replies. This textual data provides rich material for content analysis, discourse analysis, sentiment analysis and thematic exploration of community perspectives.

    \item \textbf{Visual data}: image and video content elements including the videos themselves (analyzable as complete recordings or extracted screenshots), video thumbnails, visual banners and annotations, environmental settings, camera angles and visual representations of creators themselves. Visual data facilitates ethnographic research, visual rhetoric analysis and examination of multimodal communication strategies.
\end{itemize}

\subsection{Research ethics, data privacy and API terms compliance}

\label{subsec:ethics_privacy_and_terms_compliance}

As a social media research infrastructure, the OpenTube platform operates at the intersection of public data collection, academic methodology and platform governance. Addressing ethical and legal requirements is fundamental to ensuring responsible deployment.

\paragraph{Compliance with YouTube developer policies}

OpenTube requests public YouTube data with an API key and without OAuth user authorization, so every response it receives is \enquote{Non-Authorized Data} under the YouTube API Services Developer Policies. Clause III.E.4.d allows API clients to \enquote{temporarily store limited amounts of Non-Authorized Data for as long as is necessary for the purposes of the API Client but not longer than 30 calendar days}, and clause III.E.4.e requires reasonable efforts to keep stored data consistent with the data currently available through the API \autocite{youtube_api_services_developer_policies}. The policies contain no exemption for academic or non-commercial use. The only research-specific route, the YouTube Researcher Program, keeps the same 30-day refresh obligation and allows a dataset to be fixed at a point in time only to finalize the analysis for a publication \autocite{youtube_researcher_program_terms}. OpenTube therefore applies the following retention policy:

\begin{enumerate}
    \item \textbf{30-day retention window}: every record that holds YouTube API data (channels, videos, statistics snapshots, comments and replies) carries the timestamp of its last retrieval, and a scheduled purge deletes it 30 days later, together with the sentiment results and derived metrics computed from it.

    \item \textbf{Refresh by re-collection}: re-running a saved query retrieves the current platform state and renews the retention window, which also drops content that was deleted on YouTube after the previous run.

    \item \textbf{Persistent methodological records}: projects, saved queries, effective parameters, collection run status, quota consumption and request logs describe the collection procedure rather than the platform content. They store no response bodies or YouTube resource identifiers and are kept as the auditable record of how each dataset was obtained.
\end{enumerate}

% Clause III.E.4.h, which prohibits using API data \enquote{to create new or derived data or metrics}, and clause III.E.2, which restricts aggregating API data across channels, remain in tension with any analytical tool built on the API \autocite{youtube_api_services_developer_policies}. OpenTube limits this exposure by deleting derived records within the same 30-day window, but does not claim to resolve it.

\paragraph{Data privacy and statutory compliance (Ley 1581 de 2012)}

In the Colombian context, personal data handling is governed by Statutory Law 1581 of 2012 (\textit{Ley Estatutaria de Protección de Datos Personales}) \autocite{ley1581_2012}. Although YouTube comments and channel metadata reside in the public domain, collecting user identifiers (\texttt{author\_channel\_id}) and natural language text constitutes the processing of pseudonymous personal data. OpenTube incorporates data protection by design principles:

\begin{itemize}
    \item \textbf{Pseudonymization and scope limitation}: user identification details are stored purely as technical system keys. Data analysis is strictly limited to video-level metrics and sentiment aggregations, prohibiting individual user profiling or cross-platform tracking.

    \item \textbf{Aggregation at the presentation layer}: all visual dashboards, metrics tables and exportable summary artifacts mask individual user identities, displaying sentiment classifications and engagement figures only in aggregate form.

    \item \textbf{Scientific purpose exemption}: data processing is conducted strictly for public-interest academic research, directly supporting computational social science projects such as PROMUEVA at Universidad del Valle \autocite{promueva_project}. This exemption concerns personal data protection under Law 1581 only; it does not exempt OpenTube from the YouTube API Services Developer Policies described above.
\end{itemize}

\subsection{YouTube Data API limitations and computational reproducibility challenges}

\label{subsec:youtube_data_api_limitations_and_computational reproducibility_challenges}

Beyond the diversity of methodological approaches employed by researchers, the YouTube Data API itself presents inherent technical limitations that must be carefully considered to ensure research reproducibility. Crucially, all YouTube data collection tools, whether open-source or commercial, depend entirely on the YouTube Data API, which is controlled by Google and subject to unilateral modifications without academic input. The discontinuation of the \mintinline{text}{relatedToVideoId} parameter in August 2023, which was previously essential for expanding datasets through recommendation networks, exemplifies how platform decisions can retroactively invalidate established research methodologies and prevent replication of earlier studies.

Recent empirical investigations reveal that the API's Search endpoint exhibits significant temporal variability in returned results. \textcite{efstratiou2025youtube} conducted a systematic audit by running identical queries at 5-day intervals over 12 weeks across six diverse topics, finding that Jaccard similarity between video sets declined substantially over time, demonstrating that datasets collected using the exact same historical query may differ vastly based solely on when queries are executed.

In light of the temporal decay demonstrated by \textcite{efstratiou2025youtube}, true end-to-end computational reproducibility—defined as generating identical datasets from live API queries over time—is fundamentally unachievable on dynamic platforms like YouTube. Consequently, this work adopts a two-tiered methodological framework: (1) \textbf{Auditability and Documented Provenance} during data collection, achieved by permanently logging request parameters, pagination tokens and execution timestamps (\texttt{api\_request\_logs}, \texttt{collection\_runs}) and by retaining raw payloads for the 30 days permitted by the YouTube API Services Developer Policies; and (2) \textbf{Computational Reproducibility} during analysis, obtained by applying deterministic parsing routines and documented sentiment models to the raw data while it is retained. Because a stored dataset cannot outlive that window, the reproducible unit in OpenTube is the documented collection procedure—saved query, effective parameters and request logs—rather than the dataset itself; the temporal decay described above already means that re-running a query yields a different sample, so the procedure is what another researcher can verify. Tools and frameworks that systematically document API dependencies, timestamp data collection and maintain transparent records of all methodological decisions are essential for conducting replicable YouTube research within these known limitations.

\subsection{Scrum}

Scrum is an agile project management framework that facilitates team collaboration through iterative and incremental development \autocite{schwaber2020scrum}. The framework prescribes for teams to break work into goals completed within time-boxed iterations called sprints, typically lasting two to four weeks \autocite{schwaber2020scrum}. Scrum is based on three pillars (transparency, inspection and adaptation) and emphasizes self-organization, continuous feedback and flexibility in response to changing requirements \autocite{schwaber2020scrum}. Originally developed for software development, Scrum has since been successfully applied to various complex projects requiring iterative progress and stakeholder collaboration \autocite{schwaber2020scrum}.
