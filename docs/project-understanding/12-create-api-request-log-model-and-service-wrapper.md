# 12 - Create API request log model and service wrapper

Story: US-013, Create API request log model and service wrapper.

Status note: this document describes the US-013 implementation **after** the code review of 2026-10-05 and the fixes that followed it.

## What this story added

Before this story, the app had collection runs (US-010, US-011) but no way to call YouTube. This story adds two things:

- the `ApiRequestLog` model, stored in the `api_request_logs` table. One row per YouTube API call.

- one function, `call_youtube`, in `src/api/core/youtube_client.py`. Every YouTube call must go through it, and it writes the log row.

Nothing calls `call_youtube` yet. US-015 (video discovery) is the first caller.

## Why this matters

The thesis promises that a reader can audit how a dataset was collected. A run says *that* collection happened. The request log says *how*: which endpoint was called, with which parameters, in which order, what it cost and what went wrong.

There is a second constraint. YouTube's policies allow API data to be kept for at most 30 days, but request logs are kept forever as methodological records. So a log must contain **nothing that counts as YouTube data**: no response bodies and no YouTube resource IDs (video, channel or comment IDs).

## Key concept: one wrapper, one path

If every caller built its own HTTP request, one of them would eventually forget to log. Instead there is one function:

```python
payload = call_youtube(run, "search.list", params, api_key=settings.YOUTUBE_API_KEY)
```

It:

1. rejects bad input before doing anything: an unknown endpoint, a `key` inside `params`, a `bool` value, or an empty API key all raise `ValueError`. Nothing is sent or logged.

2. creates the log row **before** the request, with `started_at` and the next `request_sequence` for that run.

3. sends one HTTP GET to `https://www.googleapis.com/youtube/v3/<resource>`.

4. completes the row **after** the request: HTTP status, number of items, next page token, `finished_at`, or `error_message` on failure.

5. returns the decoded JSON, or raises `YouTubeApiError`.

Creating the row first matters. If the process crashes mid-call, the row stays with `finished_at` empty, and that is evidence too: "a request started and never finished".

## Key concept: what a log row must never hold

| must not be stored | how the code avoids it |
| :-- | :-- |
| Response bodies | Only counts and the next page token are read from the response. |
| The API key | It goes into the request URL only. It is never part of `request_params`, `error_message` or a logger line, and tests check all three. |
| YouTube resource IDs | `id`, `channelId`, `videoId`, `parentId`, `allThreadsRelatedToChannelId` and `relatedToVideoId` are replaced by a count, e.g. `"id": {"redacted_count": 3}`. |
| YouTube's free-text error message | `error_message` keeps only the status and YouTube's reason codes, e.g. `HTTP 403: quotaExceeded`. The free text can echo request values. |

The search text `q` and page tokens **are** stored: they are the researcher's input and opaque paging markers, not YouTube data.

## Key concept: quota cost

YouTube gives each project a daily quota of units, and each endpoint costs a fixed amount. `QUOTA_COSTS` holds that table: `search.list` costs 100, and `videos.list`, `channels.list`, `commentThreads.list` and `comments.list` cost 1. An endpoint missing from the table is rejected, so no caller can log a guessed cost. A failed request keeps its cost, because YouTube charges for failed requests too.

## File-by-file explanation

### `src/api/core/models.py`

Adds `ApiRequestLog` after `CollectionRun`. It links to its run with `CASCADE` (`run.request_logs`) and has two database rules:

- `unique_api_request_log_sequence_per_run`: no two logs in one run share a sequence number.

- `api_request_log_finished_after_started`: `finished_at` is never earlier than `started_at`.

### `src/api/core/migrations/0006_apirequestlog.py`

Generated by `makemigrations`. Creates the table and both constraints.

### `src/api/core/youtube_client.py`

The wrapper. Besides `call_youtube` it holds:

- `_get_json(url)`: the real transport, using only the standard library (`urllib`), with a 30-second timeout. It turns every failure into `YouTubeApiError` with a safe message.

- `_loggable_params(params)`: copies the parameters for the log, replacing ID values with their count.

- `transport=`: a parameter tests use to swap in a fake sender, so no test ever reaches `googleapis.com`.

### `src/api/opentube_insights_api/settings.py`

Reads `YOUTUBE_API_KEY` from the environment with no default. A missing key is not silently replaced: `call_youtube` raises `ValueError`.

### `src/api/core/admin.py`

`ApiRequestLogAdmin` is view-only: you cannot add, change or delete a log by hand. Logs are evidence.

### `src/api/core/tests.py`

- `ApiRequestLogModelTests`: the two database rules.

- `CallYouTubeTests`: success, sequence numbers, page token and `part`/`fields` columns, ID redaction, HTTP error, network error, bad JSON, rejected input, and that the key never reaches the log or the logger.

- `GetJsonTransportTests`: the real transport with `urllib.request.urlopen` replaced by a stub. It checks the GET, the timeout and the error mapping.

## How the pieces connect

```text
US-015 collector (later)
        |
        v
call_youtube(run, "search.list", params, api_key=...)
        |-- reject unknown endpoint / key in params / bool / empty key --> ValueError
        |-- ApiRequestLog.objects.create(sequence=N, started_at, redacted params, quota)
        |-- _get_json(".../youtube/v3/search?...&key=...")   (or the test transport)
        |       |-- ok    --> status, items count, nextPageToken, finished_at
        |       '-- error --> status or none, "HTTP 403: quotaExceeded", finished_at
        '-- return payload, or raise YouTubeApiError

CollectionRun 1 ----< ApiRequestLog   (unique run + sequence, finished >= started)
```

## How to test manually

In the Django shell (`venv/bin/python manage.py shell`), with a fake transport so nothing reaches YouTube:

```python
from core.models import CollectionRun
from core.youtube_client import call_youtube
run = CollectionRun.objects.first()
fake = lambda url: (200, {"items": [{}, {}], "nextPageToken": "CAIQAA"})
call_youtube(run, "videos.list", {"part": "snippet", "id": "a,b"}, api_key="test", transport=fake)
run.request_logs.last().request_params   # {'part': 'snippet', 'id': {'redacted_count': 2}}
```

Then open `/admin/`, go to Api request logs, and open the row. Every field is read-only, there is no delete button, and the key `test` appears nowhere.

## Common errors

- **`ValueError: Unknown YouTube endpoint 'playlists.list'.`** The endpoint is not in `QUOTA_COSTS`. Add it there, with its real cost, if a story needs it.

- **`ValueError: YOUTUBE_API_KEY is not configured.`** Set `YOUTUBE_API_KEY` in `src/api/.env` (now ignored by git).

- **`YouTubeApiError: HTTP 403: quotaExceeded`.** The daily quota is used up. The log row still records the call and its cost.

- **The admin refuses to delete a collection run.** The run has request logs, and logs refuse deletion. This is intended: runs and their logs are kept. Deleting from code (the ORM, or the future US-040 purge) still cascades.

## Known gaps

- No retries or backoff: one failed request fails the call. The `ponytail:` comment in `_get_json` marks where retries would go.

- A page token longer than 255 characters would not fit its column. Real YouTube tokens are far shorter, so the review left this alone.
